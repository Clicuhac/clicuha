# DevOps 2.0 --- План для Clicuha

## 🎯 Мета

Створити надійну, швидку та автоматизовану систему оновлення сайту, щоб
будь-які зміни публікувалися однією дією ---
`commit → push → сайт оновлено`.

------------------------------------------------------------------------

## 🧩 БЛОК А. Порядок у репозиторії

### A1. Структура

-   `~/clicuha` --- головний репозиторій (код + git).
-   `~/public_html` --- лише результат деплою.
-   У репо повинна бути повна структура сайту: `index.php`,
    `config.php`, `functions.php`, `/nicknames`, `/admin`, `/assets`,
    `.env.example`.

### A2. Чистка

``` bash
cd ~/clicuha
git add .
git commit -m "chore: clean up structure"
git push origin main
```

------------------------------------------------------------------------

## 🚀 БЛОК B. Автодеплой 2.0

### B1. deploy.sh

Має виконувати:

``` bash
cd ~/clicuha
git pull origin main
rsync -av --delete ./ public_html/ --exclude ".git" --exclude ".github" --exclude "_trash.off"
```

### B2. GitHub Webhook

-   Repo → Settings → Webhooks
-   URL → твій deploy.php на сервері
-   Trigger → `push` у `main`

Після пушу сайт оновлюється автоматично.

------------------------------------------------------------------------

## 🧪 БЛОК C. Стейджинг

### C1. Піддомен

`dev.clicuha.com` → папка `~/dev_html`

### C2. Деплой у dev

Варіант:

``` bash
bash deploy.sh dev
bash deploy.sh prod
```

------------------------------------------------------------------------

## 🛡️ БЛОК D. Страховка

### D1. Git як бекап

-   нормальні коміти
-   швидкий відкат:

``` bash
git log --oneline -5
git checkout <commit>
```

### D2. Бекапи хостингу

-   завантажувати раз на тиждень архів сайту + БД

------------------------------------------------------------------------

## 🧠 БЛОК E. Правила

### Ніколи не:

-   не редагуємо `public_html`
-   не заливаємо файли вручну
-   не правимо структуру хаотично

### Завжди:

1.  редагуємо код у репо
2.  commit
3.  push у `dev` або `main`
4.  тест
5.  деплой через push

------------------------------------------------------------------------

## 🕹️ БЛОК F. Робочий цикл (Лань + Алекс)

1.  Визначаємо задачу\
2.  Лань готує код\
3.  commit → push у dev\
4.  dev.clicuha.com --- тест\
5.  Якщо ок → push у main

------------------------------------------------------------------------

## 🧯 БЛОК G. Антикризовий план (скорочено)

1.  Перевірити сайт\
2.  Зайти SSH\
3.  `cd ~/clicuha && git status`\
4.  Переглянути коміти\
5.  Відкат на попередній\
6.  `bash deploy.sh`\
7.  Якщо git вбитий --- заново клонувати:

``` bash
mv ~/clicuha ~/clicuha_broken
git clone https://github.com/Clicuhac/clicuha.git ~/clicuha
bash deploy.sh
```
