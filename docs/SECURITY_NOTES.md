# 🔐 SECURITY NOTES --- Clicuha

Цей документ описує правила безпеки, мінімальні вимоги, ризики, типові
загрози та рекомендації щодо захисту інфраструктури Clicuha.

------------------------------------------------------------------------

## 🛡 1. Основні принципи безпеки

1.  **Ніколи не редагувати `public_html` вручну.**\
    Усі зміни мають надходити тільки через Git + автодеплой.

2.  **Усі паролі в `.env` і конфігураціях повинні бути поза GitHub.**

    -   `.env` не зберігається в репозиторії\
    -   використовуються `.env.example` як шаблон

3.  **Сесії користувачів мають бути захищені:**

    -   `session_regenerate_id()` після логіну\
    -   secure cookies\
    -   `httponly` + `SameSite=strict`

4.  **SQL -- тільки підготовлені вирази (prepare)**\
    Жодних конкатенацій в SQL.

5.  **Усі зовнішні файли перевіряються перед завантаженням.**

------------------------------------------------------------------------

## 🧱 3. PHP-безпека

### 1) Вимикаємо небезпечні функції

У `php.ini`:

    disable_functions = exec,passthru,shell_exec,system,proc_open,popen

### 2) Режим помилок

-   На продакшені не виводимо помилки в браузер\
-   Логи --- тільки в окремий файл:

```{=html}
<!-- -->
```
    error_log = /home/.../php_error.log

### 3) Захист форм

-   CSRF токени\
-   Перевірка довжини введених даних\
-   Захист від XSS через `htmlspecialchars()`

------------------------------------------------------------------------

## 🏰 4. Безпека бази даних

-   Права користувача MySQL мають бути мінімальні:

    -   `SELECT`, `INSERT`, `UPDATE`, `DELETE`
    -   Заборонити `DROP`, `CREATE`, `ALTER` для вебкористувача

-   Обов'язково:

        utf8mb4_unicode_ci

-   Пароль до БД --- мінімум 16 символів

------------------------------------------------------------------------

## 🧨 5. Типові загрози

### 1) SQL injection

Вирішено через prepared statements ✔️

### 2) XSS

Вирішується: - `htmlspecialchars()` - очищення HTML - обмеження довжини
полів

### 3) CSRF

Потрібно впровадити: - CSRF-токени для форм\
- Перевірка по сесії

### 4) Втрачений доступ до сервера

Рішення: - зберігати резервний пароль у недоступному сховищі\
- завжди мати доступ у хостинг-панель

------------------------------------------------------------------------

## 🔥 6. Backups

1.  Автоматичні щоденні бекапи хостингу\
2.  Раз на тиждень --- ручний бекап БД і файлів\
3.  Зберігання бекапів:
    -   локально\
    -   у хмарі\
    -   на флешці як офлайн-копія

------------------------------------------------------------------------

## 🚧 7. Автодеплой --- особливі умови безпеки

-   `deploy.sh` не повинен мати права редагувати `.env`\
-   репозиторій в `~/clicuha` повинен мати власника *clicuhac*\
-   права `755` для директорій і `644` для файлів\
-   ключі доступу GitHub зберігати тільки в `~/.ssh`
