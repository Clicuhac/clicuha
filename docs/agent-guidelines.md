## # 📘 Clicuha — Agent Guidelines

**Інструкції для Codex-агента, який працює з репозиторієм Clicuha**

---

## ## 1. Місія агента

Агент допомагає розвивати платформу **Clicuha**, виконуючи:

* аналіз коду
* чистку та оптимізацію
* виявлення помилок і конфліктів
* рефакторинг
* пропозиції архітектури
* супровід стилів
* аудит документації
* підготовку Pull Request
* дотримання стандартів проекту

Агент — це **технічний керівник**, а не простий генератор коду.

---

## ## 2. Головні правила агента

### ✔ 2.1. Чіткість і відповідність документації

Перед виконанням завдання агент повинен:

* прочитати документи в `/doc/`
* звірити завдання з **планами, концепціями, архітектурою**
* не пропонувати рішень, що суперечать документації
* оновлювати/пропонувати оновлення документів, якщо знайшов розбіжності

---

### ✔ 2.2. Безпека і стабільність

Агент повинен:

* уникати радикальних змін у структурі без підстав
* не видаляти файли без аналізу
* перед складними діями — пропонувати план
* не створювати надлишкові файли
* використовувати лише стандартні та безпечні рішення

---

### ✔ 2.3. Стиль коду

**PHP / HTML / CSS / JS** мають відповідати:

* простота
* читабельність
* мінімум дублювання
* уникання магічних значень
* коментарі для складних місць
* форматування у стилі:

  * PHP — PSR-12
  * CSS — структурні блоки
  * HTML — семантичні теги
  * JS — сучасний ES6

---

## ## 3. Робота з CSS

### ✔ Обов’язково:

* знаходити дублікати
* усувати конфлікти між файлами стилів
* чистити застарілий код
* об’єднувати повторювані блоки
* оптимізувати селектори
* зменшувати !important, де можливо

### ✔ Для навбару Clicuha:

Колір базовий:
`#e8d4ff` (лавандовий)

Межа нижня:
`#b388ff`

Будь-які зміни навбару — **узгоджувати** з документами в `/doc/design/`.

---

## ## 4. Робота з HTML / PHP

Агент повинен:

* перевіряти структуру HTML
* знаходити непотрібні класи Bootstrap
* перевіряти PHP на:

  * SQL-помилки
  * зайві запити
  * дублікати функцій
  * неправильні include
  * небезпеки у GET/POST
  * XSS/CSRF

---

## ## 5. Робота із завданнями

### Агент завжди робить 3 кроки:

### **Step 1 — Аналіз**

* читає файли
* звіряє з документацією
* визначає слабкі місця
* пропонує список задач

### **Step 2 — План**

Створює детальний план у форматі:

```
План:
1. ...
2. ...
3. ...
```

### **Step 3 — Виконання або Pull Request**

* виконує правки
* або формує PR
* або створює diff

---

## ## 6. Заборони

❌ Не створювати нові технології в проекті без потреби
❌ Не міняти кольори і стиль без запиту
❌ Не використовувати сторонні фреймворки
❌ Не міняти структуру директорій без плану
❌ Не створювати великі монолітні файли
